# Local Guide — 지역 지침서(프로젝트 CLAUDE.md) 만들기

지역 지침서는 Claude가 이 폴더에서 일할 때마다 읽는 파일이다. 매 대화의 앞부분을 차지하므로 **짧고, 이 폴더에만 해당하고, 바로 행동으로 옮길 수 있는 줄**만 남긴다. 전역 지침에 이미 있는 말을 되풀이하면 토큰만 쓰고 정작 중요한 줄이 묻힌다.

좋은 지침 한 줄의 기준: "이 줄을 지우면 Claude가 이 폴더에서 실수할까?" 아니라면 지운다.

## 1단계: 위치와 기존 지침 확인 (읽기만)

1. 대상 폴더를 정한다. git 저장소면 루트(`git rev-parse --show-toplevel`), 아니면 사용자가 말한 폴더나 현재 폴더.
2. 이미 있는 지침 파일을 모두 찾는다: `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md`, 하위 폴더의 `CLAUDE.md`, `AGENTS.md`, `.cursorrules`, `.github/copilot-instructions.md`.
3. **전역 지침을 읽는다**: `~/.claude/CLAUDE.md` (Windows는 `%USERPROFILE%\.claude\CLAUDE.md`). 없으면 없는 대로 진행한다. 이 내용은 2단계 이후 "중복 제거" 기준이 된다.
4. 상위 폴더에 CLAUDE.md가 있으면 그것도 함께 로드된다는 점을 기억하고, 상위 내용도 중복 제거 기준에 넣는다.

기존 CLAUDE.md가 있으면 **새로 쓰지 말고 개선 모드**로 간다(6단계의 diff 방식).

## 2단계: 폴더 유형 판별

| 단서 | 유형 | 추가로 볼 것 |
|---|---|---|
| `package.json`, `pom.xml`, `build.gradle`, `pyproject.toml`, `requirements.txt`, `go.mod`, `Cargo.toml` 등 | 코드 | 실행·빌드·테스트 명령, 언어 버전 |
| `.md`·`.docx`·`.hwp`·`.pdf`가 대부분, 빌드 파일 없음 | 문서 | 문서 종류, 파일 이름 규칙, 문체·용어, 산출 형식 |
| 날짜·차시 이름의 폴더(`YYMMDD_*`, `week01` 등), 실습 파일 | 수업·학습 | 폴더·파일 이름 규칙, 미완성 자리표시 파일, 별도 저장소 하위 폴더 |
| `.ipynb`, 데이터 파일(`.csv`, `.parquet`), 모델 가중치 | 데이터·ML | 데이터 위치, 대용량 파일, 재현 명령, 환경 |
| 위가 섞임 | 혼합 | 해당 항목 모두. 모노레포면 하위 폴더별 CLAUDE.md도 제안 |

유형별로 무엇을 찾을지는 `references/checklist.md`를 읽는다.

## 3단계: 사실 수집 (추측 금지, 읽기 전용)

체크리스트대로 실제 파일에서 사실을 뽑는다. 핵심은 다음이다.
- **명령어**: 설치·실행·테스트·빌드·린트. `package.json`의 `scripts`, `Makefile`, `pom.xml`, README의 실행 절. 존재하는 명령만 적는다.
- **구조**: 최상위 1~2단계 폴더와 각 역할 한 줄. 모든 파일을 나열하지 않는다.
- **이름 규칙**: 파일·폴더 이름 샘플 5~10개에서 보이는 패턴.
- **Git**: `git log --oneline -20`의 커밋 메시지 형식, `.gitignore`, 하위 폴더 안의 별도 `.git`.
- **건드리면 안 되는 것**: 자동 생성물(`dist/`, `build/`, `runs/`), 대용량 파일, 비밀값 파일(`.env`, `*.pem`), 별도 저장소, 원본 데이터.
- **이 폴더만의 함정**: README·주석·이슈에 적힌 주의사항, 특이한 환경(conda 환경 이름, 특정 Python 경로, 포트).

비밀값을 발견하면 지침에 값을 절대 옮기지 않는다. "`.env`에 있음, 커밋 금지"처럼 위치만 적는다.

### 전역과 부딪히는 관습 찾기
수집한 사실을 전역 지침의 규칙 하나하나와 대조한다. 이 폴더가 실제로는 전역과 **다르게** 하고 있는 곳이 지역 지침서에서 가장 값진 줄이다. 적어 두지 않으면 Claude는 전역 규칙대로 이 폴더의 관습을 "고치려" 든다.

| 전역 규칙 예 | 이 폴더의 실제 관습 예 | 지역 지침에 쓸 줄 |
|---|---|---|
| 주석은 "왜"가 필요한 곳에만 | 수업 코드마다 `# 1. 모델 로드` 같은 단계 번호 주석 | 전역의 주석 규칙 대신 이 폴더는 단계 번호 주석을 단다 — 학습 기록용 |
| 커밋 `type(scope): 제목` | `git log`가 `FEAT : 제목` 형식 | 커밋은 `FEAT : 제목` 형식(전역 기본값과 다름) |
| 새 라이브러리는 제안만 | `requirements.txt`가 없고 수업마다 설치 | 해당 없음 — 충돌 아님 |

충돌을 찾으면 "전역의 X 대신 이 폴더는 Y — 이유"로 적는다. 관습이 일부 파일에만 보여 의도인지 불확실하면 `(확인 필요)`를 붙이고 4단계 질문에 넣는다.

## 4단계: 모르는 것만 묻기

파일로 알 수 없는 것만, **한 번에 최대 3개** 묻는다. 보통 이런 것이다.
- 이 폴더의 목적과 결과물을 누가 보는지 (예: 수업 제출용, 팀 공유, 개인 기록)
- 전역 지침과 다르게 해야 하는 점 (예: 이 폴더는 주석을 영어로, 커밋 형식이 다름)
- Claude가 절대 하면 안 되는 일 (예: `data/raw/` 수정 금지, main 직접 push 금지)

사용자가 "알아서 해"라고 하면 묻지 않고 진행하되, 추정한 항목은 초안에 `(확인 필요)`로 표시한다.

## 5단계: 초안 작성

`references/template.md`의 뼈대를 쓰고, 해당 없는 절은 지운다. 쓰는 규칙:

1. **전역과 겹치면 뺀다.** 전역에 "한국어로 답한다"가 있으면 지역에 다시 쓰지 않는다. 전역과 **다르게** 해야 할 때만 "전역의 X 대신 이 폴더는 Y"라고 명시한다. 프로젝트 지침이 전역보다 우선한다는 점을 이용하는 것이다.
2. **명령어는 그대로 복사해 쓸 수 있게** 코드 블록으로 쓴다. 경로·환경 이름까지 실제 값으로.
3. **일반론 금지.** "깔끔한 코드를 작성한다", "테스트를 잘 한다" 같은 줄은 Claude 행동을 바꾸지 못한다. "커밋 전 `npm test` 통과 확인"처럼 구체적으로.
4. **이유가 안 보이는 규칙에는 짧은 이유를 붙인다.** "`runs/` 커밋 금지 — 학습 결과물이 수백 MB". 이유가 있어야 Claude가 비슷한 다른 경우에도 판단한다.
5. **길이**: 보통 30~80줄. 100줄을 넘기면 자주 안 쓰는 상세 내용을 `docs/` 등 별도 파일로 빼고 `@docs/파일.md`로 가져오거나 "~할 때는 X 파일을 읽어라"로 안내한다.
6. **표 vs 목록**: 규칙이 3개 이상 같은 형식이면 표, 아니면 짧은 목록.
7. 지침서의 언어는 사용자가 쓰는 언어로. 명령어·경로·식별자는 원문 그대로.

개인에게만 해당하는 내용(내 PC 경로, 내 계정 이름)은 팀과 공유하는 `CLAUDE.md` 대신 `CLAUDE.local.md`(그리고 `.gitignore`에 추가)를 제안한다.

## 6단계: 자체 점검 후 보여주기

쓰기 전에 아래를 점검한다. 걸리는 줄은 고치거나 지운다.
- [ ] 전역 지침과 같은 뜻의 줄이 남아 있지 않은가
- [ ] 3단계에서 찾은 전역과의 충돌이 모두 "전역의 X 대신 Y"로 들어갔는가
- [ ] 적은 명령어가 실제로 존재하는가 (스크립트 이름, 파일 경로 확인. 가능하면 `--help`나 dry-run으로 실행 확인)
- [ ] 비밀값·토큰·개인 이메일이 들어가지 않았는가
- [ ] "이 줄을 지우면 실수할까?"에 아니라고 답할 줄이 없는가
- [ ] `(확인 필요)` 표시가 남은 항목을 사용자에게 알렸는가

그다음 사용자에게 보여준다.
- **새로 만들 때**: 전문을 보여주고 "이대로 만들까요?"라고 묻는다.
- **기존 파일이 있을 때**: 바뀌는 부분만 diff로 보여준다. 사용자가 직접 쓴 규칙은 지우지 않는다. 지우거나 합칠 줄은 이유와 함께 제안만 한다.

승인을 받은 뒤에만 파일을 쓴다. 쓴 뒤에는 경로와 줄 수, 전역과 겹쳐 뺀 항목 수를 한두 줄로 보고한다.

## 하지 않는 일
- 코드나 문서 본문을 고치지 않는다. 이 스킬의 산출물은 지침 파일뿐이다.
- 파일별 근거를 붙인 상세 컨벤션 검토 보고서는 만들지 않는다(컨벤션 분석 스킬의 몫). 필요해 보이면 제안만 한다.
- 다른 AI 도구용 파일(`AGENTS.md` 등)은 사용자가 원할 때만 만든다. 만들 때는 CLAUDE.md와 내용을 복제하지 말고 한쪽이 다른 쪽을 가리키게 한다.
